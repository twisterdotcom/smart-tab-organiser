Smart Tab Organiser

Settings & Configuration

How to Use

Click the extension icon to deduplicate tabs, refresh enabled GitHub groups, and tidy your pinned tabs. Label-group sync for toolbar clicks can be disabled below. If no tabs are pinned yet, the extension pins tabs from your list and opens any missing URLs. The icon badge shows how many duplicate tabs are open.

Right-click menu: Use the extension menu to organize tabs, reload tabs, collapse or expand groups, or open extension options.

AI Tab Organization: Use the context menu, the button on this page, or a shortcut that you assign at chrome://extensions/shortcuts. These actions deduplicate tabs first. Configure a provider below.

Actions

Duplicate Detection Settings

Configure how the extension identifies duplicate tabs.

When enabled, URLs with different query strings are treated as duplicates.
Example: example.com/?a=1 and example.com/?b=2 are considered duplicates.

When enabled, URLs are compared without their hash/anchor, but the hash is still used to determine which tab to keep (highest anchor number).
Example: example.com/#comment-123 and example.com/#comment-456 are duplicates, but the one with #comment-456 is kept.

When enabled, remaining tabs will be automatically reloaded after closing duplicates.

Pinned tabs

Define which URLs should be Chrome-pinned (compact favicon tabs on the left of the tab bar). When you run "Deduplicate and tidy pinned tabs" or organize with AI, any pinned tab not in this list will be unpinned, and matching unpinned tabs will be pinned and ordered. If no tabs are pinned yet, the extension will pin tabs from this list (opening new tabs for any URL not already open).

Exact match (no prefix): only that exact URL stays pinned (after normalizing query/hash per your duplicate settings).
Prefix match: start a line with * so any tab whose URL starts with the rest of the line stays pinned. For example, *https://mail.example.com/ keeps all sample mail pages, and *https://app.example.com/workspace/demo keeps all pages in the sample workspace.
Soft (only when already open): start with ~ so the tab is only pinned when it already exists in the window; the extension never opens it. Use ~*https://... for soft prefix or ~https://... for soft exact. Example: ~*https://app.example.com/workspace/demo keeps the sample workspace pinned only when it is already open. Leave empty to keep all currently pinned tabs as-is when tidying.

Colour for the BOOKMARKS tab group. Applied whenever you run dedupe/tidy so the group keeps this colour.

GitHub tab groups

These optional features use your GitHub token to maintain tab groups. The token stays in local storage and goes only to GitHub. Label-group colours come from these settings, not from GitHub label colours. Managed groups appear after pinned tabs in this order: BOOKMARKS, PRs, configured labels, Closed.

The extension uses this token to fetch open pull requests, issue states, and label names. The PR feature requires read:user. Private repositories also require suitable repository access.
Create a token: github.com/settings/tokens

When enabled, the extension maintains a PRs group for your open pull requests and review requests. It opens missing tabs for matching PRs from GitHub. Each dedupe or organize action refreshes this group first. Tabs that no longer match an open PR leave the group but remain open. Duplicate removal keeps the copy in PRs. Split-view tabs remain unchanged.

Colour for the PRs tab group. Applied whenever the group is refreshed.

Requirements & notes

Chrome 138+ requires about 22 GB of free disk space and an unmetered connection for the first download. GPU use requires more than 4 GB of VRAM. CPU use requires at least 16 GB of RAM and four CPU cores. Gemini Nano is smaller than cloud models, so the extension organizes tabs in batches of 20.

Loopback model server Primary

The extension sends prompts only to localhost or 127.0.0.1. The server configuration determines whether it processes data locally or forwards it elsewhere. Compatible servers include Ollama, LM Studio, llama.cpp, and vLLM.

Ollama / LM Studio setup

Ollama must be started with extension requests allowed, otherwise it rejects them: OLLAMA_ORIGINS="chrome-extension://*" ollama serve

In LM Studio, enable CORS in the local server settings; llama.cpp's server allows this by default. Enter the model name exactly as your server reports it — "Test connection" lists what it can see.

If the provider fails

This setting is off by default. If enabled, the extension tries eligible providers in order after the preferred provider fails. A local primary tries only the other local provider unless you also allow cloud fallback.

Also allow cloud providers with a saved API key after the local providers fail.
When this occurs, the AI data disclosure above applies. Leave this setting off to prevent cloud fallback.

    Organisation behaviour

    Provide custom instructions for how tabs should be organized (e.g., "group by domain", "group by topic", "prioritize work-related tabs").
    These instructions will be used when organizing tabs from the options page.

    When enabled, tabs that are already in groups will be skipped during organization.
    When disabled, all tabs will be reorganized into new groups.
    Pinned tabs and groups named "BOOKMARKS" and "PRs" are always preserved, regardless of this setting.

    When set, only groups that have more than N tabs are preserved. Groups with N tabs or fewer are ungrouped and sent through AI organization again.
    AI will also never create a new group with N or fewer tabs; such tabs go into Misc.
    Example: with 2, groups with 3+ tabs are preserved; groups with 1–2 tabs are re-organized, and new groups have at least 3 tabs.

    This feature may not work well if the number is higher than 3.

    When enabled, the AI will intelligently merge ungrouped tabs into existing groups where appropriate.
    This works best when "Preserve existing groups" is also enabled. The AI will analyze existing groups and merge new tabs into them.
    Pinned tabs and the "BOOKMARKS" group are always preserved; these options apply to other groups only.

    When enabled, after organization, tabs inside each group are ordered alphabetically by page title (A–Z).
    BOOKMARKS and PRs groups are not reordered.

    When enabled, clicking the extension icon will deduplicate tabs AND organize them using AI.
    When disabled, the extension icon deduplicates tabs and applies your pinned-tab list (default behavior).

    Settings are automatically saved in extension-local storage.
